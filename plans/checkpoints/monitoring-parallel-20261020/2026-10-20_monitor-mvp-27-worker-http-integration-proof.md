# Monitoring MVP: skutečná worker → HTTP integrační cesta

## Goal
Dodat hermetický test i skutečně nasazenou a bounded live ověřenou cestu worker→audit package→existující intake HTTP pro všechny podporované proposal sections. Jednotlivé read tasky už zahrnují vlastní nasazení a HTTP ověření; tato dodávka doplňuje skutečnou celkovou producer cestu, neodkládá jejich deployment na závěr. Proposal `proposal-20261019-150954-c8891f`, `slice-retry-terminal`. Nenahrazovat chybějící source/identity/auth proof mocks synteticky vyrobených událostí.

## Files / inputs
`plans/monitoring/runtime-producer-context-contract.md`, `worker-instrumentation-contract.md`, `mvp-reference-20261019.md`; actual worker entrypoint a intake/router packaging, audit package, existující `contracts/openapi-processing-monitor.yaml`, focused `test_processing_monitor_worker_http_integration.py` v skutečném test layoutu a `plans/monitoring/worker-http-deployment-smoke.md`. Existující intake FastAPI/App Runner je read API owner; žádná nová aplikace/server/proxy.

## Required change
- Přes skutečný source entrypoint spustit syntetický benign document fixture s fake externími provider/blob/queue ports, ale skutečnými business orchestration callers+audit boundary/persistence+HTTP routes. Ověřit stejné event/run/attempt identity napříč actual calls a GET. HTTP data nesmí vznikat ručním seedingem událostí mimo tested worker; nezávislé sink tests jen doplňují, nejsou E2E.
- Reuse existující read auth seam s trusted identity→case oprávněním, scope document404/403, private,no-store, read503. Shared key sám není case authorization. Chybějící trusted seam je blocker a konkrétní interface na hosta/owner, ne oprávnění vymyslet claims či oslabit isolation.
- Pro supported canonical branches zdokumentovat success/failure/retry fragment a absence audit → unknown, cache reuse bez nového model call, signature disabled/returned failure, partial publish bez run terminal, lost/late/duplicate observations. Explicitně evidovat pokud stage skutečný producer vůbec nemá, nedoplnit business funkci kvůli zelenému testu.
- Ověřit build inclusion/import audit package ze skutečného worker a intake artifactů, deklarované env/IAM/resource potřeby pouze jako diff/checklist existujících owners bez credentials. Neplést dvě byte-shodné source files s provenance celého deployed image. Před deploymentem inspect/preserve existující konfiguraci, uchovat recovery artifact a použít revision/concurrency guards. Rutinní instalace a in-place deployment do existujícího AWS test cíle jsou podle AGENTS.md součást dodávky; žádné broad konfigurace/permissions nebo nový deployment framework.
- Host smoke runbook: přesné artifact/source digests k ověření; stávající supported synthetic upload/queue cesta, očekávané bezpečné event/HTTP assertions, limity nákladů a odstranění test fixture pouze podle skutečných supported operators. Bez zavedení reprocess/replay endpointu nebo tvrzení, že neprovedený command je důkaz. Agent provede a zaznamená skutečné test deployment/AWS HTTP smoke v rozsahu standing authorization. Pokud jeho skutečný runtime nemá podporované oprávnění, Jackie provede konkrétní operator krok v rámci stejného zadání; neobcházet denial a neuzavírat source-only jako hotové. Agent doladí zjištěné chyby tohoto scope a doplní runtime závěr. Nevyvozovat historickou reprodukovatelnost bez reference/verze.

## Boundaries
Pouze wonderfulkb a existující AWS TEST cíl: source/tests/docs, nutná instalace a guarded in-place test deployment, bounded syntetická cesta přes existující podporované rozhraní a skutečné HTTP. Žádný replay reálných dokumentů, nová placená inference/provider call bez příslušného povolení, soukromý dokument, secrets v evidenci, produkční/nesouvisející resources, broad permissions, scheduler zásah, nový runtime/outbox/index/projekce/UI/artifact content API. Credentials používat pouze přes existující bezpečný owner, ne číst či vypisovat do reportu; deny neobcházet. Žádné změny business retry/lease/claim/fencing nebo task lifecycle. Nové moduly doménové, ne state.py/service.py/utils.py. Reference known fixtures musí být lokální, nikdy soukromý reálný PDF.

## Verification
Implement the TDD cycle using skill:tdd. Focused full-path hermetické integration tests, skutečné entrypoint/build import proof a registrované gates. Explicitní tabulka source/hermetic/installed/deployed/live-function-verified s pravdivými skutečnými důkazy a všechny concrete blockers, nikoli obecné success. Pokud runtime cesta dosud nefunguje, dodat konkrétní blocker místo DONE z runbooku. YAML/routes/fixtures souhlasí; žádné whole-history scan nebo synthetic complete/latest claim. Závěr nesmí označit deploy nebo live worker→HTTP za funkční bez skutečně provedené runtime evidence; samotný připravený smoke postup nebo lokální test není dokončení.
