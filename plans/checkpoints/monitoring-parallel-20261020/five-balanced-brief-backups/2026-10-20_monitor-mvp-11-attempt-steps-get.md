# Monitoring MVP: jeden GET pozorovaných kroků pokusu

## Goal
Processing Monitor API vrátí bounded okno pozorovaných krokových událostí konkrétního runu/pokusu. Malá read část slice 4, bez nové uložené projekce a tvrzení o úplné historii.

## Files/functions
`be-intake/app/processing_monitor_routes.py`, `be-document-processing/src/document_processing/audit/audit_queries.py`; jediný `be-document-processing/contracts/openapi-processing-monitor.yaml` a focused FastAPI test vedle stávajících monitor GET. Proposal `proposal-20261019-150954-c8891f`, `slice-source-validation`, `read-api`, `instrumentation`; konkrétní kontrakt v `plans/tasks/2026-10-20_monitor-mvp-10-source-validation-events.md`.

## Change / exact read semantics
- Jediný nový GET `/v1/cases/{case_id}/processing/documents/{document_id}/runs/{run_id}/steps?attempt_no=...`, povinný kladný attempt_no, limit1–100, next_token. Tentýž intake/FastAPI App Runner router a auth/no-store/read503 kontrakt jako existující events/attempts; ne nový server ani proxy. Neplatný parametr/token = konzistentní 4xx existujícího routeru.
- Reuse dokumentový Query s jedním omezeným evaluated event oknem a filtr run+attempt. `items` jsou krokové observations, ne celohistorická agregace: event_id, sequence, occurred_at, type, stage, run_id, attempt_no, a pouze pokud doložené page_number/duration_ms/error_code. U source_validation page_number chybí. Přenášet jen existující allowlist, bez document content. Žádný vymyšlený step_id nebo execution status.
- StepStarted/StepFinished/StepFailed jsou krokové observations. S rozšířením page-transcription event kontraktu se do stejného view mapují i PageCompleted/PageFailed jako jediný terminální outcome příslušné stránky; bez vytváření duplicitního StepFinished/StepFailed. Toto mapování definovat jako rozšířitelný explicitní allowlist, nyní nevymýšlet chybějící typy.
- JSON items/next_token/observed_at; výslovná response `coverage=partial` (observation window, není úplný seznam kroků). Nespárovat eventy napříč okny čtením celé historie. Chybějící start/konec není failed/success, chybějící hodnoty neznámé; terminal-only observations nezahazovat, nedopočítávat trvání z timestampů. Každý event nejvýše jednou podle uložené idempotence. I prázdné items mohou mít continuation.
- Cursor obsahuje a ověřuje case/document/run/operation=steps/attempt_no a poslední VYHODNOCENOU pozici, nikoli poslední nalezený krok. Jiný attempt, run nebo operation token odmítne. Žádný Scan, scan-until-filled, úplné přehrávání, totals či nový index. Refresh od začátku, bez snapshot/incremental garance.
- Absence RunQueued/AttemptStarted nebo shody v aktuálním okně neznamená neexistenci runu/pokusu. Existující document/case authorization seam rozhoduje scope404/403; nutný read-source failure503, nikoli empty success. Samotný sdílený key nevytváří per-case oprávnění; chybějící trusted seam je konkrétní blocker, ne oprávnění jej vymyslet. Všechny odpovědi včetně chyb private,no-store.
- Cíleně upřesnit tento observation-window DTO v JEDINÉM YAML; starý širší Step/status/projection návrh není mandát na jeho implementaci. Zachovat již dodané GET kontrakty a explicitně popsat partial/empty continuation.

## Boundaries
Pouze wonderfulkb. Bez producer hooku, stored step projekce, celého lifecycle, run list/detail, page GET, UI/content, nového runtime/indexu nebo nesouvisejících business writes. Neměnit aktivní task briefy ani execution sémantiku. Hermetické observations nedokládají živý worker.
