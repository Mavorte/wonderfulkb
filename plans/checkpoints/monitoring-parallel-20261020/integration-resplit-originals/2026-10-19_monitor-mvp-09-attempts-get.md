# Monitoring MVP: jeden GET pozorovaných pokusů

## Goal
Processing Monitor API vrátí jen pokusy skutečně pozorované z AttemptStarted, ve stejném intake routeru.
## Files/functions
`be-intake/app/processing_monitor_routes.py`, interní `audit_queries.py`, jediný `be-document-processing/contracts/openapi-processing-monitor.yaml`; focused FastAPI test attempts GET.
## Change
GET `/v1/cases/{case_id}/processing/documents/{document_id}/runs/{run_id}/attempts`. Reuse bounded event Query/window jako run-events: stránka items = observed AttemptStarted (event_id, attempt_no, occurred_at), next_token a observed_at. Žádná uložená projekce, agregace všech stránek ani falešný total/status/attempt duration. Pole je event-observation view, ne kompletní seznam všech execution pokusů; idempotentní event neopakovat, případné konfliktní observations nesloučit do tvrzení o business stavu. RunQueued může chybět, ale AttemptStarted s doloženým runem je viditelný. Scope token obsahuje case/document/run/operation; auth/no-store/read503 podle prvního GET, missing document404. Jediný YAML upřesní partial coverage a empty page with continuation.
## Boundaries
Pouze wonderfulkb; žádné run list/detail, steps/pages, retry terminal souhrn, nový index/service či producer hook. Aktuální SQS receive count ani business snapshot nejsou náhradní zdroj. Hermetická fixture není live claim důkaz.
## Verification
Focused pytest: dva pozorované pokusy, izolace druhého runu, chybějící RunQueued, bounded okno/continuation a cross-operation token odmítnut, auth/read503. FileReceived/run-events kompatibilní. Implement the TDD cycle using skill:tdd.

Neodkládat nasazení na závěrečný integrační task nebo samostatný smoke. Platí též pro rozšíření DTO/allowlistu již existujícího GET, nejen novou route.

Žádný nový server, Lambda/API Gateway, deployment framework nebo automatický merge/publikace. Nevymýšlet workflow, které repo nemá.
2. Agent tuto změnu dodá end-to-end včetně rutinního test deploymentu, pokud to umožňují jeho skutečná oprávnění a existující deployment rozhraní. Použít standing AWS test authorization v AGENTS.md, zachovat stávající env/IAM/auth a nesouvisející konfiguraci, před změnou uchovat ověřený recovery artifact/config, použít revision/concurrency guards a bounded čekání na skutečné dokončení rollout/health. Pokud nový producer ještě nedodává daný event, rozlišit nasazený GET od NEOVĚŘENÉ live obsahové větve; skutečně doložený dřívější syntetický event smí posloužit bez replay.
