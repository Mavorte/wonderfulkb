# Case Client: GET /cases napříč všemi klienty

## Výsledek
Michal19.10.2026 15:40 výslovně požaduje novou metodu pro listování všech cases bez povinného klienta A plný cyklus implementace→nasazení→HTTP integrační testy→opravy→redeploy v témže implementačním pokusu. Výsledkem je funkční nová verze na existujícím testovacím AWS endpointu, ne pouze zdrojový kód. Plánování zůstává read-only; mutace až v implementaci s běžně přezkoumaným a schváleným plánem. Přidat GET /cases do jediné existující Python komponenty be-case-client; zachovat POST /cases, GET /cases/{case_id}, GET /clients a GET /clients/{client_id}/cases. Vrací plné veřejné Case objekty, tedy i case_id/client_id, nikoli jen pole ID. Žádný nový server, backend ani frontend.

## Kontrakt
- GET /cases bez client_id vrací200 `{"cases": [...], "next_token": <string nebo null>}`. Žádný povinný ani fiktivní top-level client_id. Prázdná tabulka/seznam→200/prázdné pole, ne404.
- limit default50, rozsah1–100 a next_token podle existujících konvencí. Nezavádět další filtry jako nový feature; pokud plán zvolí převzetí existujícího status=open, dokumentovat a testovat konzistentně. Malformed/nesprávný typ/route-bound token→400. Token jiné routy/backendu/dotazu/limit nesmí být přijat.
- Seznam je stránkovaný přes všechny klienty, včetně klienta který už není active; žádná smyčka přes /clients ani ověřování existence/statusu klientů před každým řádkem. Žádné JOIN čtení klientů. Vrátit jen existující veřejná CASE_FIELDS, zachovat metadata/Decimal JSON a nevystavovat interní atributy.
- Globální pořadí není garantované; DynamoDB Scan neslibuje newest-first. Neprovádět full-table scan + in-memory sort před první stránkou a neslibovat snapshot při souběžných zápisech. Stávající klientské listování si zachová svůj newest-first GSI kontrakt.

## Implementační hranice a zdroje
Rozšiř existující CaseClientRepository, MockCaseClientRepository, DynamoDBCaseClientRepository a handler, nevytvářej paralelní protokol. Aktuální `_list(kind='cases', client_id,...)` předpokládá konkrétního klienta: nelze jen předat None, protože dělá client lookup a GSI query. Nová jasně odlišená globální cesta potřebuje Scan nad cases tabulkou a vlastní cursor schema/fingerprint. Sdílej funkční části, nepřidávej generický framework.

DB kontrakt je již zdokumentovaný: externí cases tabulka má pouze case_id PK, existující client-created-index je per-client. Pro malý syntetický/hackathon dataset použij omezený stránkovaný Scan existující tabulky. Žádný nový GSI, kopie tabulky, seed nebo změna schématu. Omez interní stránky/čas a správně pokračuj po prázdné filtrované stránce. LastEvaluatedKey/pozice musí obnovit průchod i při dosažení response limitu uprostřed SDK stránky; nad stabilním fixture datasetem žádné duplicitní/ztracené řádky ani cyklický token. Prázdná odpověď může mít pokračovací token, pokud vypršel interní budget. Není-li možný pravdivý resume point a selže budget/SDK, vrať bezpečnou chybu, ne falešný konec.

API je chráněné stejným x-api-key/usage plan jako ostatní routy, nejde o tenantové přihlašování. Nepřidávat anonymní veřejnou výjimku. Rozšířit OpenAPI additivně s odpovídající verzí, SAM Gateway GET událost/route a dokumentaci. Zkontrolovat již existující Scan oprávnění: případnou template úpravu omezit jen na cases ARN a mock/DynamoDB režim; žádné dynamodb:* nebo Resource:*. Cloudové změny jsou výhradně úzce povolené v provozním rozsahu níže.

Scope: be-case-client/** a související repo-local dokumentace/plány. Zachovat serverové UUIDv4/plain-create POST chování z aktuální komponenty, nevrátit caller ID/idempotent200.
