## Feasibility and bounded design

**Inference, not implemented:** preserve the existing business analysis schema and queued/expired lease behavior, while adding a separate runtime state table keyed by `(case_id, document_id)` that contains `active_run_id`, state, and monotonic attempt counter. Enqueue creates a fresh opaque run ID once per accepted queue operation, writes it as active runtime identity, and puts it on the SQS message. On ambiguous `SendMessage` outcome, a retry must reuse the same queued run ID (not allocate a second). Worker claim is one DynamoDB transaction: conditional update of business row retaining its current condition (`queued` OR `processing` with `updated_at < now-930s`, per runtime evidence lease) plus conditional runtime-row update for the same active run, incrementing attempt counter and recording the claim. Only after transaction success emit AttemptStarted with `(run_id, attempt_no)` and pass that context explicitly into pipeline/page seams. Duplicate queue deliveries that fail claim do not increment or emit another start. No business-stage fencing or status redesign is implied.

RunQueued should be emitted only for a confirmed accepted queued run, with idempotent event identity, and recovered/re-emitted on retry of an uncertain send using the same run ID. The precise crash boundary between durable state, event persistence, and SQS send needs transactional-outbox/idempotency treatment; DynamoDB transaction cannot include SQS. Do not claim exact delivery without defining that boundary. A single active run per document aligns with existing business-row lease/claim semantics; a force/requeue operation supersedes the prior active run. Old in-flight messages then fail active-run check. This introduces identity fencing only for run selection, not business result writes; preventing an expired worker from overwriting business analysis after lease recovery would require separate business fencing and is explicitly out of scope.

## Risk and unknowns

- Source-level target is a historical candidate commit, not checked-out trigger files; runtime equivalence is proven for common + worker only, not enqueue handler/full build. Confirm owner and exact deployed compatibility when implementing; do not infer all artifacts identical.
- Queue send ambiguity / process crash around status update, runtime record, event write, and SQS send is the main correctness risk. Event store delivery policy and atomic-outbox mechanism need a bounded implementation decision/test, not an open-ended architecture investigation.
- Existing `run_document` writes business state and S3 artifacts without run-level fencing. Explicit context enables attribution, not safe concurrent output isolation. Lease is 930 seconds; longer executions can overlap a reclaimed attempt. Preserve current lease behavior; don't promise stale-worker isolation.
- Transcript cache keys are document/page/model based, not run based; reuse is intentional, so page-outcome events should distinguish cached observation from provider invocation and never imply a provider call for cache hits.
- No inference that provider SDK exposes page lifecycle hooks; source shows direct synchronous `transcribe()` call only.
