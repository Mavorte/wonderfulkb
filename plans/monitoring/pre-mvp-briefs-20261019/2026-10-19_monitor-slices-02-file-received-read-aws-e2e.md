# Monitoring slice 1B: dokumentové events API a celé AWS HTTP E2E

## Cíl a konkrétní vstupy
Dodat čtecí polovinu FileReceived: autorizovaný GET /v1/cases/{case_id}/processing/documents/{document_id}/events nad skutečným document-scope deníkem, plus bezpečně nasaditelný přírůstek a E2E skutečný intake → audit persistence → nasazené HTTP API v existujícím AWS test prostředí eu-central-1. Source-only nebo ručně vložený auditní řádek není dokončený slice.

Vstupy: proposal docs/proposals/proposal-20261019-150954-c8891f_monitoring-zpracovani-dokumentu-prubeh-mezivysledky-a-audit.md (slice-file-received, read-api, delivery); be-document-processing/PROCESSING-MONITOR-API.md; interní package document_processing/audit/ a jeho plans/monitoring/slice-01-write-contract.md. Zachovat skutečný FileReceived hook po S3+metadata commitu a import/build seam intake. Pokud technický vstup chybí, pojmenovat přesně chybějící rozhraní; nevytvářet alternativní deník.

## Rozsah čtecí cesty
1. Minimální bounded query/DTO v interním package: audit_queries.py a podle potřeby audit_http_api.py, existující HTTP/router a AWS adapter pouze delegují. Bez nové služby, root modulu, frontend/proxy aplikace či UI. Nevytvářet generické nové soubory queries.py, api.py nebo storage.py; stávající api.py lze rozšířit delegací.
2. Ověřit aktuální skutečnou AWS route, deployed artifact a business identity ownery; checked-in pk/sk/payload adapter není automaticky živé schéma. Stávající wonderfulkb-uw-documents a analysis zůstávají beze změny. Přítomnost dokumentu smí být čtena kvůli scope/404, ale nevytváří nový business list/detail endpoint.
3. Ověřit existující autentizaci A case oprávnění skutečného calleru. Serverový API klíč ani pouhá existence case nejsou důkaz oprávnění. Použít skutečný podporovaný seam bez vymyšlené identity, důvěry v klientský case header nebo otevření API. Pokud žádný skutečný case-authorizer neexistuje, uvést konkrétní security blocker, nevydávat veřejnou route s API-key-only ochranou. Credentials server-only.
4. Scope je case+document. FileReceived nemá run_id. Bounded limit/next_token, tokeny validované a vázané na scope/query; deterministické occurred_at,event_id řazení. Zdokumentovat token expiraci/revision a podporovaný inkrementální refresh. Opožděně zapsaný event mezi stránkami i po posledním čtení musí být následným bounded refreshem nalezitelný bez full-history reloadu/Scanu; neslibovat transakční snapshot ani úplnost fail-open deníku. sequence není čas uložení.
5. observed_at = čas čtení, ne heartbeat. Odlišit not_configured, not_instrumented a skutečně prázdnou historii; chybějící event není business failure. Neexistující identita/scope 404, nepovolený přístup 403 nebo konzistentní existence masking podle ověřeného kontraktu, potřebný read-source failure 503. Všechny odpovědi včetně chyb mají Cache-Control: private, no-store. Žádné sensitive exception texty, filename, text, credentials ani raw S3 reference.
6. Aktualizovat jediný existující OpenAPI YAML be-document-processing/contracts/openapi-processing-monitor.yaml pro aktuální API-only scope a nyní dodanou operaci; odstranit aktivní business collection/detail, artifact/content a UI ambice. Pozdější slice operace označit jako návrh, ne nasazený příslib; zachovat budoucí kontrakt 10 slices. Nepřidávat druhý YAML. Guide a proposal musí souhlasit s implementovaným dílčím API.

## Ověření a operational handoff
- Contract/auth/pagination/error testy: pozitivní identita, cross-case/document denial, chybějící/malformed auth, neexistující case/document, token z jiného scope, invalid/expired token, více stránek, pozdní insert/refresh, nedostupný nutný zdroj a redakce. Lokální fault injection neoznačovat za AWS ověření.
- Nasaditelný intake artefakt skutečně obsahuje a používá jediný interní audit package. Připravit minimální template/route/config/IAM změny, verifikovat packaging a regression upload. Instalaci, konfiguraci a in-place deployment provede host dle standing authorization v AGENTS.md; to je součást výsledku 1B, ne důvod zakončit slice source-only. Žádná nová deploy jednotka. Ověřit existující test cíl, zachovat konfiguraci, recovery artefakt a revision/concurrency guards; žádná production/public platform publikace nebo broad access změna.
- Připravit repo-local automatizovatelný HTTP E2E test ve jménu odpovídajícím processing monitoru. Bounded syntetický nový soubor musí projít skutečným nasazeným intake a jeho FileReceived se přečte přes skutečný nasazený GET se stejnou case/document identitou a bez runu. Znovu upload stejného obsahu nezdvojí event. Neprovádět replay reálných dokumentů ani nejednoznačně idempotentních requestů; test fixture a počet syntetických writes evidovat. Žádná placená inference není potřeba pro intake.
- Skutečné HTTP negativní auth/scope a dosažitelný bezpečný read-failure scénář; fault-injection jen na hermetických fixturech, nesměrovat ani nerozbíjet sdílené live tabulky. Není-li live 503 možné bezpečně vyvolat, odděleně přiznat hermetický důkaz a konkrétní live omezení, nevymýšlet runtime důkaz.
- Focused API+intake/audit testy, zvolený OpenAPI validator a všechny registrované gates; neoslabovat je. Opravy této cesty patří této implementaci, ne ručním změnám hosta.

## Acceptance a evidence
Source, lokální testy a runtime delivery jsou samostatná tvrzení. Slice je dodaný až s plans/monitoring/slice-01-aws-e2e.md: skutečný cílový endpoint a region, ne-secret deployed artifact digest/version, čas ověření, syntetické identity/provenance, safe HTTP statusy a relevantní redigované DTO, auth/scope důkazy, bounded query důkaz a oddělené fault-injection výsledky. Reálný event nesmí být vložen přímo místo produceru. Chybějící oprávnění/auth seam nebo deployment dokazatelně reportovat jako blocker, nikoli hotovo. Bez dokumentového obsahu či credentials v Mission Control/reportu. Mimo scope: runs/attempts/steps/pages/audit snapshot, artifact-content, business list/detail, UI a refaktor execution pipeline.
