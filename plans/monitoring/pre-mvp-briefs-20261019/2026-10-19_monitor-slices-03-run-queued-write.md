# Monitoring slice 2A: RunQueued — skutečné enqueue a auditní persistence

## Cíl a vstupy
Rozšířit existující interní audit pouze o zápis RunQueued po skutečném úspěšném předání běhu frontě a o minimální bounded run access. Žádné HTTP run endpointy ani worker lifecycle eventy. Zachovat již dodaný FileReceived a jeho čtení.

Ověřit a dokumentovat reálný runtime enqueue seam, nedělat nový business job backend ani měnit business storage podle starého adapteru.

## Implementace
1. Charakterizovat současný job create/conflict, opakované complete_upload, callback chyby a no-op local enqueue; zachovat business odpovědi, stav, chyby, queue zprávy a retry/lease/publish chování.
2. Rozšířit stávající audit_events.py, audit_listener.py, audit_storage.py v be-document-processing/src/document_processing/audit/; žádná paralelní implementace auditu a žádné nové obecné events.py/storage.py/utils.py. Business zná malý injektovaný protokol, ne DynamoDB items, auditní catch/retry logiku ani vlastní audit konfiguraci.
3. RunQueued jen po potvrzeném návratu skutečného enqueue/send_message. Vytvoření jobu, zamýšlené enqueue, lokální no-op a neúspěšný send nejsou událost. Rozlišit potvrzený queue adapter od callbacku, který nic neodesílá. Po úspěšném sendu selhání auditu nesmí zneplatnit business úspěch ani vyvolat další enqueue. Opatrně ošetřit idempotenci prvního RunQueued pro stejný run a retry doručení; nevymýšlet queue exactly-once.
4. Obálka case_id, document_id, run_id a skutečný occurred_at; schema_version/event_id/sequence dle společného deníku. FileReceived zůstává document-only. Event idempotency je run-scope transition identity. RunQueued říká enqueue, nikoli start workeru, délku čekání nebo úspěšné zpracování. RetryEnqueued, AttemptStarted a další eventy se nyní neimplementují.
5. Zachytit nejvýše jednou známý povolený historický kontext z uloženého jobu: mode, pipeline_version, prompt_version, ocr_model, extraction_model, provider, api z bedrock_api, region z bedrock_region; job_id/config_hash volitelně. Reference konkrétního vstupu je veřejně opaque source_artifact_id v artifact_ids, interně jen potřebná známá source_version/source_sha256. Preferovat dostupnou neměnnou referenci. Nekopírovat celý config/job, dokumentová data ani credentials. Chybějící hodnoty zůstanou unknown, nikoli dnešní environment; konfigurace není důkaz model call, verze není content hash, signature config dnes uložen není.
6. Stejný append-only deník; přidat jen doložený minimální odvoditelný run index/projekci pro bounded list/detail/filter, žádné nové plné run manifesty ani business autoritu. Partial run musí být nalezitelný z existujících run-scoped eventů i bez RunQueued. Protože se ostatní producenti ještě neimplementují, tento stav prokázat explicitními syntetickými fixtures, ne přidáním dalších runtime hooků. Odvozený index nesmí po expiraci zdrojů předstírat dochovanou historii; neaktivovat nepotvrzenou TTL politiku.
7. Fail-open chrání také tvorbu a serializaci kontextu. Krátký konečný I/O timeout bez auditního retry/outboxu/recovery/replay. Audit neřídí scheduler, nemění lease/fencing, nepřidává nový proces a nezapisuje do business tabulek.

## Testy a acceptance
- Úspěšný skutečný queue adapter zaznamená RunQueued teprve po send success se stejnou run identitou jako job. Failure/no-op nic; opakování neduplikuje logický event. Diferenciální NoOp / healthy / failing / timeout / malformed-context audit zachová přesně business writes, odpovědi, výjimky, počet queue sendů a jejich payloady.
- Context je z uloženého jobu, i při následně změněném worker environment; safe allowlist/nullability, opaque externí reference a unknown chybějící zdroj. Žádná falešná inference či úplná reproducibility.
- Bounded run access a document/run isolation, partial run bez RunQueued, idempotentní index update a pozdní event. FileReceived zůstává bez runu a jeho existující API/regresní testy dále procházejí.
- Focused service/bootstrap/audit testy a všechny registrované gates bez oslabení. Žádná placená inference nebo live message replay; zde source a lokální write-path důkaz, nikoli hotový nasazený slice.

Bez secrets a obsahu dokumentů. Nenasazovat nový backend jako náhradu chybějícího živého seam; případný rozpor označit konkrétně.
