# Monitoring slice 2B: runs API, historický kontext a celé AWS HTTP E2E

## Cíl a technické vstupy
Dodat run list/detail a run events nad stejným deníkem, rozšířit dokumentové events o RunQueued a dokončit live AWS cestu skutečný enqueue → persistence → autorizované HTTP čtení. Zachovat FileReceived end-to-end. Autorita: docs/proposals/proposal-20261019-150954-c8891f_monitoring-zpracovani-dokumentu-prubeh-mezivysledky-a-audit.md (slice-run-queued, read-api, delivery), be-document-processing/PROCESSING-MONITOR-API.md, jediný existující monitor OpenAPI, interní audit package a plans/monitoring/slice-02-write-contract.md. Zdrojový service.py/bootstrap.py nemusí odpovídat dnešnímu živému AWS produceru; skutečné napojení se ověřuje, ne předstírá.

## Čtecí implementace
Pod prefixem /v1/cases/{case_id}/processing/documents/{document_id} implementovat GET /runs, GET /runs/{run_id}, GET /runs/{run_id}/events a rozšířit existující GET /events. Run events je filtr stejného document event deníku; FileReceived v run filtru není. Konkrétní case/document/run musí být ověřený, ne jen syntakticky přijatý.

Použít audit_queries.py a případně audit_http_api.py ve stávajícím document_processing/audit/ plus tenkou delegaci existujícího routeru/AWS adaptéru. Žádná nová app/service/root modul, UI, proxy, generic runs.py/queries.py/storage.py. Neměnit business tabulky, klíče, S3 lifecycle, job backend ani scheduler.

Run detail je minimální explicitně partial projekce doložených faktů, nikoli předčasně hotový DTO všech fází. Známý RunQueued nedokazuje worker start, queue wait, attempt count, dokončení, nula chyb/stran ani úplnost historie. Run bez úvodního eventu je dohledatelný z run-scoped deníku/indexu a označen partial; chybějící RunQueued se nevymýšlí. Tuto variantu testovat synteticky bez přidávání dalších producerů.

Historický kontext ukazuje pouze povolené uložené hodnoty nebo ověřenou neměnnou referenci konkrétního běhu: mode, deklarované pipeline/prompt verze, modely, provider/API/region, volitelný job_id/config_hash a opaque source_artifact_id. Neznámé/zaniklé hodnoty jsou unknown/unavailable. Nikdy nepoužít dnešní environment, současný jiný job nebo mutable obsah jako tehdejší snapshot. Konfigurace nedokazuje inference ani přesný source hash; nevracet celý job/config, raw S3 klíče, dokumentová data či credentials. Artifact list/content/presigned download jsou mimo scope.

Všechny kolekce jsou bounded limit/next_token a token je vázaný na case/document/run/query; pozdní event i run musí být následným podporovaným bounded refreshem nalezitelný bez neomezeného Scanu/full-history reloadu. Zachovat document occurred_at,event_id řazení a dokumentovat run ordering/revision/token expiraci. observed_at je čas čtení, žádný heartbeat nebo recorded_at.

Znovu použít a ověřit skutečný auth + case-authorizační seam; API key sám ani existence case nestačí. Cross-case/run přístup odmítnout konzistentně. Chybějící identita/scope 404, nepovolené 403 či ověřený existence masking, chyba potřebného zdroje 503. Odlišit not_configured / not_instrumented / skutečně empty. Cache-Control: private, no-store na všech odpovědích a chybách. Case-authorizer blocker nepřekrýt dummy stubem nebo širokým oprávněním.

## Testy, deployment a skutečné E2E
- Hermetické API/contract testy: oba event scopy a FileReceived regrese, více runů téhož dokumentu, cross-case/document/run denial, neexistující run, partial bez RunQueued, neznámý kontext, změna worker environment, bezpečné chyby, read failure, invalid/expired/cross-scope tokeny, pozdní event/run mezi stránkami a po vyčerpání.
- Upravit jediný stávající OpenAPI/guide jen o dodané run operace a partial/unknown význam; žádný business list/detail, UI, content nebo ostatní lifecycle endpointy. Focused service/bootstrap/audit/API testy, OpenAPI validace a registrované gates bez oslabení.
- Existující AWS test prostředí eu-central-1: připravit instalovatelný artefakt, minimální route/IAM/config/template změny a opakovatelný HTTP E2E. Host přímo vlastní bezpečnou instalaci a in-place deployment dle standing authorization AGENTS.md včetně původu/digestu artefaktu, recovery a revision/concurrency guards; live delivery je součást výsledku tasku, ne source-only příslib. Žádná production/public platform publikace, nová deploy jednotka nebo rozšiřování access policy mimo nutný scope.
- Bounded syntetický nový vstup přes skutečnou existující upload/queue cestu musí potvrzeně projít send_message a vrátit tentýž run v nasazeném GET /runs, detailu, run events a document events. Přímý insert auditu/mock SQS/local no-op není live producer důkaz. Potvrzení sendu uchovat bezpečně (technical identity/ack), ne ručním odebráním zprávy sdílenému workeru. Opakované GET zachová identitu/kontext a regrese live FileReceived je ověřena.
- Ověřit auth/scope negativně přes skutečné HTTP; fault-injection/read-failure, které nelze na shared test prostředí bezpečně vyvolat, označit odděleně jako hermetické s konkrétním live omezením. Nerozbíjet sdílený backend kvůli chybovému testu.
- Žádný replay reálných dokumentů nebo nejednoznačně idempotentních requestů. Použít nový malý syntetický/native vstup bez dodatečné placené inference, pokud to skutečná podporovaná runtime cesta dovoluje. Pokud enqueue automaticky spustí neautorizovanou placenou inference nebo chybí bezpečný podporovaný scénář, uvést přesný blocker; nevypínat worker, neprovádět credential/provider přepínače a nevymýšlet prod-only test hooks. Žádné další lifecycle eventy kvůli E2E.
