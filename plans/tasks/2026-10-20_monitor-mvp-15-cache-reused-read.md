# Monitoring MVP: použití cache ve stávajícím stránkovém API

## Goal
Stávající document/run events a pages GET zobrazí pozorované PageCacheReused odlišně od nové práce; žádný nový endpoint ani uložený latest Page stav. Malá read část slice 6.

## Files/functions
`be-document-processing/src/document_processing/audit/audit_queries.py`, `be-intake/app/processing_monitor_routes.py` pouze delegace/DTO podle potřeby, jediný `be-document-processing/contracts/openapi-processing-monitor.yaml`; focused FastAPI test `be-intake/tests/test_processing_monitor_cache_reused.py` (zachovat skutečný existující test layout). Vstupní kontrakt: `plans/tasks/2026-10-20_monitor-mvp-14-cache-reused-event.md`, pages observation-window v `2026-10-20_monitor-mvp-13-attempt-pages-get.md`; proposal `slice-cache-reused`.

## Change
- Rozšířit explicitní allowlist EXISTUJÍCÍHO GET `/v1/cases/{case_id}/processing/documents/{document_id}/runs/{run_id}/pages?attempt_no=...` o PageCacheReused. Stejná uložená událost je dostupná i document/run events; nezavádět druhý event nebo další HTTP collection. Item obsahuje společné observation scope/ID/type/time/sequence + cached_status, známé cached_method/cached_model a známé opaque artifact_ids. Public DTO nepřebírá interní S3 klíče, raw Page ani obsah.
- JSON stále items/next_token/observed_at, coverage=partial. Cached status je completed NEBO failed, není business/latest page status; cached metoda/model neznamenají provider call v aktuálním pokusu. Žádný completed count/total/procento či vykázaná nová inference. Různé skutečné observations jedné stránky mohou zůstat samostatné, nepřevádět reuse na PageCompleted nebo StepFinished a nepřičítat další zpracovanou stránku.
- Jeden bounded document Query evaluated window s run/attempt/type filtrem. Nezměnit cursor scope case/document/run/operation=pages/attempt_no ani poslední vyhodnocenou pozici. Empty items s next_token legitimní. Bez Scan, doplňovací smyčky, replay celé historie, nové projekce/indexu, snapshot/incremental garance nebo lookup dnešního cache objektu.
- Chybějící RunQueued/AttemptStarted/původní cache evidence není důvod zahodit doložený reuse fragment. Nedoložený původ/cache obsah zůstává unknown/unavailable, žádné nové content/artifact endpointy. Steps nepředstírají nový vykonaný krok jen proto, že stránka byla použita z cache.
- Zachovat skutečnou case autorizační hranici, document scope404/403, nutný read-error503 a private,no-store včetně chyb; neimprovizovat case claims ze sdíleného klíče. Cíleně doplnit JEDINÝ YAML včetně cached_* významu, partial observation a prázdného pokračování, zachovat stávající endpointy.

## Boundaries
Pouze wonderfulkb. Žádný producer hook, nový server/proxy/route, cache read/write, OCR/provider call, business/lease/retry/execution změna, nové stored entity/projekce, nesouvisející live business writes ani content UI. Doménové názvy souborů, žádné pages.py/state.py/utils.py. Endpoint fixtures nejsou worker→HTTP proof; skutečný producer hook zůstává navazující source integrací, ale nasazení tohoto read přírůstku a live HTTP ověření jsou součástí tohoto tasku.

## Verification

Bounded query count, empty continuation, cross-operation/attempt/run token odmítnut, auth/scope/no-store/read503. Žádné cache/model I/O; předchozí pages/steps/events chování a registrované gates zachovat. Žádná plošná fault matice nebo live cache replay.
