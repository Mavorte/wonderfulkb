# Monitoring MVP: pozorovaná extrakce ve stávajícím steps API

## Goal
Stávající steps a document/run events GET ukážou skutečně předané extraction observations bez dokumentových hodnot. Malá read část slice 7, žádný nový endpoint nebo lifecycle souhrn.

## Files/functions
`be-document-processing/src/document_processing/audit/audit_queries.py`, `be-intake/app/processing_monitor_routes.py` jen DTO/delegace podle potřeby, jediný `be-document-processing/contracts/openapi-processing-monitor.yaml`; focused FastAPI test `be-intake/tests/test_processing_monitor_extraction.py` (zachovat skutečný existující test layout). Kontrakty: `plans/tasks/2026-10-20_monitor-mvp-16-extraction-events.md`, `2026-10-20_monitor-mvp-11-attempt-steps-get.md`; proposal `slice-extraction`.

## Change
- Explicitně podpořit stage=extraction pro StepStarted/StepFinished/StepFailed ve STÁVAJÍCÍM GET `/v1/cases/{case_id}/processing/documents/{document_id}/runs/{run_id}/steps?attempt_no=...`. Document/run events vracejí stejné uložené události, bez duplikace. Reuse stávající mapování pokud již genericky tento typ korektně přijímá; nevytvářet redundantní handler/framework jen kvůli nové stage.
- Item je observation s event_id/type/sequence/occurred_at/run_id/attempt_no/stage, známou duration_ms a bezpečným error_code dle kontraktu, bez page_number. Žádné fields, quotes/evidence, labels, prompt/result/raw errors, počty vytěžených hodnot nebo tvrzení o model call. Platný StepFinished není důkaz všech nalezených polí ani konce runu. Bez observed startu nesyntetizovat start; bez terminálu nevymýšlet failed/success/duration.
- JSON items/next_token/observed_at a coverage=partial; jeden bounded evaluated document Query s run/attempt/type filtrem, last evaluated cursor case/document/run/operation=steps/attempt_no. Empty items s continuation legitimní; žádné Scan, scan-until-filled, párování přes celou historii nebo nový index/stored step projekce. Zachovat existující pořadí a refresh od začátku bez snapshot/incremental garance.
- Scope pokusu je povinný, nezaměnit poslední pokus ani použít mutable business snapshot jako historii. Chybějící RunQueued/AttemptStarted nebrání čtení pozorované extrakce. Chybějící pozorování není důkaz, že extrakce nebyla provedena; žádný success pro prázdnou sadu. Pages view nedostane non-page extraction jako stránkovou práci.
- Zachovat skutečnou case authorization/scope404/403, nutný read-error503 a private,no-store i na chybách. Neodvozovat per-case práva ze shared key a nezavádět nový auth framework. Jediný YAML upřesní stage/allowlist/partial response a sémantiku, nepřibírat legacy širší DTO/endpointy.

## Boundaries
Pouze wonderfulkb. Bez nového endpointu/serveru/proxy, live producer hooku, nesouvisejících cloud business writes/model call, změny extrakce/queue/retry/lease/business/execution, obsahu/UI/artifact API, lifecycle snapshotu či nové projekce. Nové moduly doménově kvalifikované, ne steps.py/state.py/utils.py. Hermetická HTTP fixture není důkaz nasazené extrakce; canonical worker hook/build zůstávají další source integrací; deployment tohoto read přírůstku a live HTTP ověření se však provádějí už v tomto tasku.
