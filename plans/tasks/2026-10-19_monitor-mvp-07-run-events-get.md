# Monitoring MVP: jeden GET událostí konkrétního runu

## Goal
Processing Monitor API přidá pouze run-scoped timeline ve stejném FastAPI routeru jako dokumentové events.
## Files/functions
`be-intake/app/processing_monitor_routes.py`, interní `audit_queries.py`, `be-document-processing/contracts/openapi-processing-monitor.yaml`; focused FastAPI test vedle prvního events GET.
## Change
GET `/v1/cases/{case_id}/processing/documents/{document_id}/runs/{run_id}/events`. Stejná intake App Runner adresa, JSON items/next_token/observed_at, limit1–100, no-store a skutečný case-authorizační seam. Reuse document Query: pevně omezené evaluated event okno, run filter se scope-bound continuation z poslední vyhodnocené pozice; dovoleno empty items s next_token. Žádná smyčka načítající historii až do naplnění výsledné stránky, žádný Scan. FileReceived bez runu nepatří do run timeline. Run, který není v tomto okně pozorován, není prohlášen neexistujícím; prázdná kolekce není tvrzení o kompletnosti. Read error503, document/case scope404 podle existující auth politiky. Aktualizovat jediný YAML.
## Boundaries
Pouze wonderfulkb. Žádný další server, list/detail runů, run index, incremental refresh, producer hook nebo nesouvisející business writes. Neřešit chybějící run identitu vytvářením business backendu. Hermetický API test není live queue důkaz.
## Verification
Focused test s FileReceived a dvěma runy: správný filtr, bounded evaluated okno přes stránku bez shody, pokračování bez ztráty, cross-run token odmítnut, auth/scope a read failure503. Existující FileReceived GET beze změny. Implement the TDD cycle using skill:tdd.
