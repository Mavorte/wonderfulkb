## Approach
- Introduce one execution-only DynamoDB table from `trigger/template.yaml`, PAY_PER_REQUEST, partition key `pk` (S, `CASE#<case_id>#DOC#<document_id>`), sort key `sk` (S). `sk=STATE` retains current opaque run ID, monotone generation, attempt counter and last claim token/time; immutable `sk=REQUEST#<enqueue_key>` maps **every** accepted logical enqueue key to its allocated run/generation and remains after a later generation. Never TTL the counter or request mappings while old messages can recur; never copy business fields or audit events. Add table name to enqueue/worker environment and narrowly scoped table read/write/transaction IAM; audit IAM/env stays scoped to the existing audit table.
- Treat `enqueue_key` as stable logical request key: stream uses its INSERT record identity (eventSourceARN + SequenceNumber, with case/document); backfill must persist/reuse a caller-provided command key for terminal/forced requeue, and a queued resend retains current generation. Allocate opaque `run_id` as a value in an owner-committed DynamoDB transaction, never infer it from SQS, clock, hash or audit. First strongly read the immutable request mapping (including old generations); transact business **existing** conditional queued transition, state CAS/create, and conditional request mapping put. A late duplicate key bound to an older generation returns stale without touching current business row or sending a message. On conditional conflict strongly read mapping+state+business and retry boundedly or return existing status; request mapping enables crash/ambiguous-commit readback across later generations. Queued resend reuses persisted generation/message; crashed send never allocates a second generation. Preserve `force`, expired processing eligibility, partial/failed and existing row attributes. Execution-store failures before allocation leave business untouched and fail the enqueue record; failures after commit recover via persisted key.
- New document messages carry explicit versioned `run_id` + generation; version 1 case messages stay unchanged. `parse_message` accepts legacy document v1 only against a *legacy-bound* generation bootstrapped conditionally for an already queued/processing pre-upgrade row; reject stale v1 against any subsequently created generation without requeueing a newer run. Distinguish old messages with no provable legacy binding (retryable/recovery handoff, not fabricated run) from stale old messages with established newer binding (skip). Missing/unavailable ledger for a new-version message is retryable execution failure; confirmed generation mismatch is a harmless stale duplicate. Test old-message/new-generation race and describe migration/recovery of queued legacy rows.
- Make `Context.send` return SQS `MessageId` and typed send status. Confirmed iff SDK response contains successful MessageId; definite rejection iff a known non-accepting validation/client error; transport timeout, unknown server error, or crash after acceptance = ambiguous. No speculative audit on ambiguous/rejected. Retried ambiguous sends may duplicate SQS messages, same generation; next confirmed response is the only RunQueued observation (audit idempotent). No outbox/replay/resend scheduler. Preserve stream partial-batch failure and backfill failure behavior; document the non-observable crash-after-acceptance audit gap.
- Claim with DynamoDB `TransactWriteItems`: conditionally update analysis `queued` or `processing` older than 930s with the **same** `processing_status`/`updated_at` write; CAS ledger on matching run/generation and expected attempt count, SET `attempt_no=old+1`, `claim_token=<per-call operation token>`, `claim_at`. Consistent pre-read supplies expected counter; transaction race retries boundedly. On ambiguous transaction response, consistent read of both items and token confirms the already committed attempt before retry; never increment twice within the same invocation. Fresh worker invocation after expired lease legitimately creates next ordinal even for identical SQS message ID. Conditional losers, terminal, valid lease and stale generation return unclaimed with no increment. Preserve existing pipeline/worker business writes; do not add a new business fencing or supersession rule. If ledger/transaction/read is unavailable, fail *before* successful claim or pipeline invocation; after an ambiguous commit with unprovable readback fail record and allow 930s lease/SQS retry (no substitute ID). Flag the unavoidable baseline difference: claim cannot proceed while execution store is down, whereas prior business-only claim could; favor authoritative identity over an unsafe fallback.
- Return immutable `ExecutionContext(case_id, document_id, run_id, generation, attempt_no, claim_token)` from successful claim; pass explicitly `worker_handler.process_document` → `pipeline.run_document(..., execution_context=...)` and only genuinely needed downstream calls. Keep `Options` shared only for clients/rate limiting, no execution identity in cached Options/ENV/globals. Preserve document result, row field set, case step and DLQ behavior.
- Add `run_queued`/`attempt_started` to single injected listener in `be-document-processing/src/document_processing/audit/audit_listener.py`; build stable event IDs from owner run/attempt boundaries there, validate/type/serialize/store in audit package, bound sink timeout and swallow all audit failures there. Invoke once after confirmed enqueue / committed claim respectively; no producer-side event construction, catch-and-retry, identity allocation or audit authority. Ensure read dispatch of existing event types still round trips.
